# 📦 SuttaCentral Offline Data ZIP Structure

This document describes the structure and optimization of the `data.zip` bundle generated by the GitHub Action pipeline. This bundle is designed to be fully compatible with the Saddhamma mobile app's `DataService`.

## 📂 ZIP Hierarchy

The ZIP file follows the standard Bilara data structure wrapped in a base folder, ensuring compatibility with the mobile app's extraction and path resolution logic. All JSON files within the archive are **minified** (no whitespace).

```text
data.zip
└── data/                      # Root wrapper (App flattens this)
    ├── sutta_index.json       # Master index
    ├── menus/                 # Navigation & Metadata
    └── bilara-data-published/  # Base content folder
        ├── root/
        │   └── pli/
        │       └── ms/        # Pali root texts
        ├── translation/
        │   └── en/            # English translations
        ├── comment/
        │   └── en/            # English comments
        ├── legacy/            # Legacy HTML fallback texts
        └── legacy_sutta_map.json # Legacy UID mapping
```

---

## 🚀 Optimization Details

### 1. Compatibility Features
- **Wrapper Folder**: All core content is placed inside `bilara-data-published/` to match the app's `baseDir` logic.
- **Path Consistency**: Paths in `sutta_index.json` are stored relative to their respective base directories (e.g., `sutta/dn/dn1_root-pli-ms.json`), allowing the app to construct full paths dynamically.

### 2. Pruning (Unused Data Removed)
To keep the bundle size minimal (currently ~18.5 MB), the following components are **explicitly excluded**:
- **Languages**: All non-English translations and non-Pali roots are removed.
- **Context Data**: `html/`, `variant/`, and `reference/` folders are excluded.
- **Metadata**: Author blurbs and raw metadata files (except those in `menus/`) are omitted.
- **System Files**: `.git`, `node_modules`, `package.json`, and all markdown files (`.md`) are stripped.

### 3. Minification & Compression
- **Minification**: Every `.json` file added to the zip is processed through a minifier that removes all unnecessary whitespace.
- **Compression**: The archive is generated using **JSZip** with **DEFLATE** compression at **Level 9** (Maximum).

---

## 🛠️ Build Pipeline

The bundle is created daily via the [Daily Data Sync](.github/workflows/daily-sync.yml) workflow:
1. **Fetch**: Pulls the latest data from `suttacentral/bilara-data`.
2. **Cleanup**: Runs `scripts/cleanup_bilara.js` to remove non-English content.
3. **Index**: Runs `scripts/build_index.js` to generate the master mapping.
4. **Bundle**: Runs `scripts/generate_data_bundle.js` to perform minification and create the final `data.zip` with the correct hierarchy.
